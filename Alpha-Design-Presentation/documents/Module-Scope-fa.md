# مرزبندی هفت افزونهٔ پیشنهادی

| افزونه | خروجی‌های اصلی | نمونهٔ معیار پذیرش |
|---|---|---|
| هستهٔ آلفا | نقش‌ها، مجوزها، شناسه‌های مشترک، تنظیمات و زیرساخت پنل | نقش غیرمجاز نتواند دادهٔ حساس را از رابط یا API دریافت کند. |
| پذیرش و ثبت‌نام | فرم معرفی، کد پیگیری، کانبان، تماس‌ها و نتیجهٔ معارفه | جابه‌جایی مرحله تاریخچه را حفظ کند و قطعی‌شدن ثبت‌نام اطلاعات را دوباره ایجاد نکند. |
| نوبت‌دهی | برنامهٔ کاری، ظرفیت، تعطیلی، رزرو و تقویم | درخواست‌های هم‌زمان نتوانند بیش از ظرفیت نوبت ثبت کنند. |
| پروندهٔ دانش‌آموز | داده‌های فردی، خانواده، تحصیلی، اسناد و سوابق | اطلاعات از پذیرش منتقل و مدارک با مجوز مشخص ارائه شوند. |
| خدمات و امور مالی | خدمت، قرارداد، تخفیف، پیش‌پرداخت، تراکنش، اقساط و بررسی رسید | جمع پرداخت تأییدشده و مانده صحیح باشد؛ اصلاح مالی سابقه را حذف نکند. |
| پیام‌ها و اعلان‌ها | قالب پیام، مخاطب، رویداد، یادآوری و سوابق ارسال | رویداد برای مخاطب مجاز و طبق زمان‌بندی اجرا و نتیجه قابل پیگیری باشد. |
| گزارش‌ها و انتقال اطلاعات | گزارش ترکیبی، Excel/PDF، تطبیق و اعتبارسنجی ورود اکسل | رکورد ناقص و تکراری شناسایی و جمع‌های مالی با مبدأ تطبیق داده شوند. |

## ارتباط‌ها

- همهٔ ماژول‌ها از هسته برای هویت و مجوزها استفاده می‌کنند.
- پذیرش از نوبت‌دهی برای زمان جلسه و از پرونده برای انتقال ثبت‌نام قطعی استفاده می‌کند.
- مالی به شناسهٔ معتبر دانش‌آموز و خدمات متکی است.
- اعلان‌ها، رویدادهای مجاز پذیرش، رزرو و مالی را دریافت می‌کنند؛ نبود سرویس پیامک نباید ثبت پرونده را خراب کند.
- گزارش‌ها و انتقال اطلاعات باید محدودهٔ مجوزهای همان کاربر را رعایت کنند.
- قطع یا غیرفعال‌کردن یک افزونه باید پیام وابستگی مشخص داشته باشد و باعث خطای کل سایت نشود.
- فایل‌های پنل React به تفکیک امکانات مربوط قابل بسته‌بندی‌اند؛ نام‌گذاری و APIهای مشترک در هسته هماهنگ می‌شوند.

## خروجی هر مرحله

نسخهٔ ZIP ماژول مربوط، شرح تغییرات، روش نصب و ارتقا، مستند استفاده و نتیجهٔ آزمون سناریوهای توافق‌شده. مالکیت کد اختصاصی، نحوهٔ تحویل دسترسی‌ها و شرایط پشتیبانی باید در قرارداد تعیین شوند.
